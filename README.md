## 1. Что было не так в исходном коде

Исходный код был написан "под SQLite", а в заданиях (лаб. 2) и на InfinityFree используется <b>MySQL<b>. Поэтому:

| Проблема                                                                                                                        | Почему это плохо                                                                                                                  | Как исправлено                                                                                                       |
| ------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| Названия таблицы и столбцов на русском, в кавычках `'Номер'`                                                                    | В MySQL кавычки `'...'` — это для текста, а не для имён. Скрипт выдаст ошибку. Кириллица в именах — источник проблем с кодировкой | Латинские имена с префиксом (`EV_Organizer`, `EV_O_name` и т. д.), как в примере из лаб. 2 (`VR_Brand`, `VR_D_name`) |

| Нет связей между таблицами                                                                                                      | Это одна плоская таблица                                                                                                          | Добавлены `FOREIGN KEY` (связь "один-ко-многим")                                                                     |

## 2. Три пункта задания от учителя

### 1) "Сменить имя"

Таблица `Организаторы` переименована в <b>`EV_Organizer`<b> (EV = _Events_), а все столбцы получили понятные латинские имена. Так же оформлены лабораторные работы в группе (`VR_Brand`, `VR_Corner`, `VR_Dashcam`).

Если учитель имел в виду <b>имя самой базы данных<b> — оно задаётся при создании БД на InfinityFree (см. шаг 3 ниже). Там имя получит автоматический префикс вида `if0_12345678_`, например `if0_12345678_events`. Лучше уточнить у учителя, что именно он имел в виду.

### 2) "Проиндексировать повторяющиеся выражения"

Это значит: если одно и то же слово/фраза встречается в таблице много раз, его записывают <b>один раз<b> в отдельную таблицу (индексную, справочную) под номером, а в основной таблице пишут только этот номер.

Было (текст повторяется):

```
Анимашки | Часовая игровая анимация | Шоу мыльных пузырей
Звездочки | Часовая игровая анимация | ШДМ
Джунгли парк | Часовая игровая анимация | Мастер-класс
```

Стало (в основной таблице только номера):

```
Анимашки     | 1 | 1
Звездочки    | 1 | 2
Джунгли парк | 1 | 7
```

А расшифровка номеров лежит в индексных таблицах:

- <b>`EV_Service`<b> — основные услуги (9 записей): `1 = Часовая игровая анимация`, `2 = Шоу мыльных пузырей` …
- <b>`EV_Extra`<b> — дополнительные услуги (8 записей): `1 = Шоу мыльных пузырей`, `7 = Мастер-класс` …

Связь "один-ко-многим": одна услуга из справочника может быть у <b>многих<b> организаторов.

## 3. Объяснение кода `events_db.sql` по частям

### Удаление старых таблиц

```sql
SET FOREIGN_KEY_CHECKS = 0;
DROP TABLE IF EXISTS EV_Organizer;
DROP TABLE IF EXISTS EV_Service;
DROP TABLE IF EXISTS EV_Extra;
SET FOREIGN_KEY_CHECKS = 1;
```

`DROP TABLE IF EXISTS` удаляет таблицу, если она уже есть, — скрипт можно запускать много раз без ошибок. Проверку внешних ключей на это время отключаем, иначе MySQL не даст удалить таблицу, на которую кто-то ссылается.

### Индексные таблицы

```sql
CREATE TABLE EV_Service (
    EV_Service_id   INT NOT NULL,
    EV_Service_name VARCHAR(100) NOT NULL,
    PRIMARY KEY (EV_Service_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

- `INT` — целое число (номер);
- `VARCHAR(100)` — текст до 100 символов;
- `NOT NULL` — поле нельзя оставить пустым;
- `PRIMARY KEY` — первичный ключ: номер уникален, по нему находят запись;
- `ENGINE=InnoDB` — движок, который умеет внешние ключи (без него связи не работают);
- `CHARSET=utf8mb4` — кодировка, чтобы русский текст не превращался в "????".

`EV_Extra` устроена точно так же.

### Основная таблица

```sql
CREATE TABLE EV_Organizer (
    EV_O_id          INT NOT NULL,
    EV_O_name        VARCHAR(50) NOT NULL,
    EV_O_description VARCHAR(200),
    EV_O_service     INT NOT NULL,
    EV_O_extra       INT NOT NULL,
    EV_O_price_main  INT,
    EV_O_price_extra INT,
    PRIMARY KEY (EV_O_id),
    INDEX (EV_O_name),
    FOREIGN KEY (EV_O_service) REFERENCES EV_Service (EV_Service_id),
    FOREIGN KEY (EV_O_extra)   REFERENCES EV_Extra (EV_Extra_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

- `INDEX (EV_O_name)` — индекс для быстрого поиска по названию организатора;
- `FOREIGN KEY (EV_O_service) REFERENCES EV_Service (EV_Service_id)` — внешний ключ: в `EV_O_service` можно записать <b>только<b> номер, который реально есть в `EV_Service`. Записать услугу №99 не получится — MySQL выдаст ошибку. Это и есть защита от "мусора" в данных.

### Заполнение данными

```sql
INSERT INTO EV_Service (EV_Service_id, EV_Service_name) VALUES (1, '...'), (2, '...');
```

Сначала заполняются <b>индексные<b> таблицы, потом основная. Иначе внешний ключ будет ссылаться на номер, которого ещё нет, и вставка не пройдёт.

### Запросы

```sql
SELECT * FROM EV_Service;    -- показать справочник услуг
SELECT * FROM EV_Extra;      -- показать справочник доп. услуг
SELECT * FROM EV_Organizer;  -- основная таблица (пока только с номерами)
```

Последний запрос собирает всё вместе через `INNER JOIN`:

```sql
SELECT o.EV_O_name AS 'Организатор', s.EV_Service_name AS 'Оказываемая услуга', ...
FROM EV_Organizer AS o
INNER JOIN EV_Service AS s ON s.EV_Service_id = o.EV_O_service
INNER JOIN EV_Extra   AS e ON e.EV_Extra_id   = o.EV_O_extra;
```

- `AS` — даёт короткий псевдоним таблице (`o`, `s`, `e`) или столбцу (красивый заголовок);
- `INNER JOIN ... ON ...` — "подставь вместо номера соответствующую запись из справочника". В результате получается таблица как в исходном задании, но с названиями вместо номеров.

## 4. Пошаговая инструкция: загрузка на InfinityFree

> Интерфейс сайта иногда меняется, названия кнопок могут немного отличаться.

<b>Шаг 1. Регистрация.<b> Зайти на https://www.infinityfree.com → <b>Sign Up<b>, ввести почту и пароль, подтвердить почту по ссылке из письма.

<b>Шаг 2. Создание хостинг-аккаунта.<b> В личном кабинете нажать <b>Create Account<b> → выбрать бесплатный домен/поддомен (например, `myevents.rf.gd`) → придумать пароль от аккаунта → <b>Create Account<b>. Подождать несколько минут, пока аккаунт активируется.

<b>Шаг 3. Создание базы данных.<b>

1. Открыть аккаунт → <b>Control Panel<b> (кнопка входа в панель).
2. Найти раздел <b>MySQL Databases<b>.
3. В поле имени ввести, например, `events` → <b>Create Database<b>.
4. Сайт сам добавит префикс: итоговое имя будет вроде `if0_12345678_events`.
5. <b>Записать<b> (пригодятся): имя БД, имя пользователя (`if0_12345678`), MySQL-хост (вида `sql123.infinityfree.com`), пароль (тот же, что от аккаунта — в панели "vPanel Password").

<b>Шаг 4. Открыть phpMyAdmin.<b> Там же, в списке баз данных, нажать <b>Admin<b> / <b>phpMyAdmin<b> рядом с созданной базой. Откроется управление БД.

<b>Шаг 5. Выбрать базу.<b> В левом меню кликнуть по своей базе `if0_..._events`.

<b>Шаг 6. Импорт скрипта.<b>

1. Вкладка <b>Import<b> ("Импорт").
2. <b>Choose file<b> → выбрать `events_db.sql`.
3. Кодировка — `utf-8`, остальное оставить по умолчанию.
4. Нажать <b>Go<b> ("Вперёд") внизу страницы.

<b>Шаг 7. Проверка.<b> Слева должны появиться 3 таблицы: `EV_Organizer`, `EV_Service`, `EV_Extra`. Открыть каждую (вкладка <b>Browse<b>) и убедиться, что данные на месте и русский текст читается нормально. Можно также на вкладке <b>SQL<b> выполнить итоговый `SELECT ... INNER JOIN` и посмотреть результат.

<b>Шаг 8. Что отправить учителю.<b> Обычно достаточно: скриншоты таблиц из phpMyAdmin (Browse) и/или ссылку/скриншот входа на сайт, плюс сам `.sql`-файл. Уточнить у учителя формат сдачи.

### Возможные проблемы

| Проблема                                       | Решение                                                                                                                    |
| ---------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| Ошибка про `CREATE DATABASE` / "Access denied" | В скрипте нет `CREATE DATABASE` — это правильно. Убедитесь, что перед импортом выбрана <b>именно созданная база<b> (шаг 5) |
| Вместо русского текста "????" или "Ð..."       | При импорте выберите кодировку `utf-8`; таблицы уже создаются с `utf8mb4`                                                  |
| Ошибка `Cannot add foreign key constraint`     | Проверьте, что все таблицы `InnoDB` и что справочники заполняются раньше основной таблицы (в скрипте так и сделано)        |
| Файл не загружается (слишком большой)          | Наш файл маленький, такого быть не должно; проверьте, что выбран правильный файл                                           |

## 5. Заметки для отчёта / на что обратить внимание

- <b>Проверить с учителем:<b> в лабораторных 1–2 требуется <b>3 основные таблицы<b> (например: заказы, опции, пользователи) с 2 и более индексными таблицами к каждой и <b>не менее 40 строк<b> суммарно. Сейчас в БД одна основная таблица (`EV_Organizer`) и две индексные, всего 29 строк (12 + 9 + 8). Если учитель требует полный набор — надо добавить таблицы, например `EV_Client` (пользователи) и `EV_Order` (заказы), связанные с `EV_Organizer`.
- Значение <b>`ШДМ`<b> в исходных данных непонятно (возможно, "Шоу дыма и…"?). Оставлено как есть — стоит расшифровать.
- Цена `0` у части дополнительных услуг оставлена как в оригинале. Если это означает "услуги нет / цена неизвестна", можно заменить на `NULL`.
- "Часовая анимация" (организатор №9) и "Часовая игровая анимация" оставлены отдельными записями, как в исходных данных. Если это одна и та же услуга — объедините их в справочнике.
- Пароли пользователей в таблицах не хранят в открытом виде (в лаб. 1 они указаны для примера) — в реальной БД используют хэши.
